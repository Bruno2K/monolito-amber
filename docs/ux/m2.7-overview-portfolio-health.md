## Product decisions

1. **Health & Portfolio are derived/read-model.** Never a manually maintained authoritative health status. May be cached/materialized later but must be reproducible from source facts.
2. **Every indicator is explainable.** Contributing signals + deep-link to source surfaces (Planning, Entregas, Coordenação, Gates/Exceptions, Documentos, Workload, Calendars).
3. **Portfolio = actor-visible Projects only.** Rollups from that set only. External collaborators = assigned Projects only. No org-wide leak (no hidden-project name placeholders, no org-total counts for external).
4. **Health requires `project.read`.** Each signal independently respects source AuthZ; prefer suppress protected details over weakening AuthZ.
5. **Gate summaries preserve READY ≠ RELEASED.** Counts show BLOCKED / READY / RELEASED / RELEASED_WITH_EXCEPTION distinctly. No invented gate AT_RISK label.
6. **Thresholds/weights = versioned product policy (v1)** documented in UX (Policy frame + this doc) — not hidden heuristics; not a health SoT.
7. **Shell M2.1 preserved:** `Ativo=Visão Geral` / `Ativo=Todos os Projetos`.
8. **No dashboard builder;** no user-configured widgets in M2.7.
9. **Workload warnings are privacy-safe** (% allocation only; no cost/salary PII; >100% allowed as warning).
10. **AuthZ:** UI affordances only; backend authoritative when implemented.

## Product policy v1 (thresholds & weights)

Documented in frame `M2.7 — Policy — Thresholds & Weights v1` (`290:14036`):

- Prazo: Task late >0d or Milestone AT_RISK → CRÍTICO (peso 1.0)
- Entregas: 1 overdue → ATENÇÃO; ≥2 → CRÍTICO (0.8)
- Coordenação: Issue ALTA/CRÍTICA open → CRÍTICO (1.0); IMPACTED PENDING >3d → ATENÇÃO (0.6)
- Governança: 1 BLOCKED → ATENÇÃO; ≥2 → CRÍTICO (0.9); READY counted separately (never as RELEASED)
- Documentos: current stale >14d → ATENÇÃO (0.5)
- Recursos: allocation >100% → ALERTA allowed (0.7)
- Rollup: any CRÍTICO → CRÍTICO; else any ATENÇÃO/ALERTA → ATENÇÃO; else OK
