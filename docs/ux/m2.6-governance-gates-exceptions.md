## Product decisions

1. **READY ≠ RELEASED.** Evaluate never auto-releases. Release requires explicit `gate.release` confirmation (NORMAL or WITH_EXCEPTION).
2. **Formal Exception is the sole bypass.** No override / forceRelease affordance anywhere in the experience.
3. **Exception coverage ≠ SATISFIED.** Gate detail shows two distinct columns: `SATISFIED` and `coveredByException`.
4. **RELEASED ≠ RELEASED_WITH_EXCEPTION.** Distinct badges, copy, and confirmation paths.
5. **SoD:** requester cannot approve/reject own Exception; requester cannot release using own Exception. Dedicated restricted states.
6. **Revoke / expiry** may return Gate to BLOCKED on re-eval; expiry is derived from `expiresAt` and does not invent an `EXPIRED` status; historical release rows remain immutable.
7. **Governance reads upstream** (Documents / Coordination / Planning). Deep-links re-auth; UI does not edit upstream owners.
8. **Exception is requirement-specific** (no gate-wide blanket).
9. **Canonical states only:** `NOT_READY | BLOCKED | READY | RELEASED | RELEASED_WITH_EXCEPTION`. No invented labels (e.g. AT_RISK).
10. **AuthZ:** UI affordances only; backend authoritative. MFA / recent-auth implied for privileged actions.

## Adversarial self-review (fixed before ready)

### BLOCKER (fixed)

1. **Auto-release risk** — READY frame keeps explicit “Liberar gate…” CTA; confirmation required; copy states evaluate never releases.
2. **SATISFIED conflation** — Detail table has separate `SATISFIED` and `coveredByException` columns; amber callout states invariant.
3. **Override affordance** — No forceRelease/override control; BLOCKED frame lists only legal paths.
4. **RELEASED badge collision** — Distinct purple `RELEASED_WITH_EXCEPTION` vs blue `RELEASED`.
5. **SoD missing** — Dedicated Restrições frame + review/confirm copy for self-approve and self-release.

### IMPORTANT (fixed)

6. Shell uses Governança children `Gates` / `Exceções Formais` (not Equipe).
7. Exception form requires requirement picker (no blanket).
8. Revoke/expiry → BLOCKED + immutable history called out.
9. Upstream deep-link re-auth note on evidence inspector.
10. System states + narrow + a11y frames present; prototype ≥ M2.5 density.
11. Oversized status badges and fixed-width copy no longer overlap or clip at desktop and narrow widths.
12. Exception expiry is represented as derived coverage loss while the canonical status remains `APPROVED`.
