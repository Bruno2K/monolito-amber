## Product decisions

1. **Activity = read-only timeline of material operational history.** Not a chat feed; no composer, reply, or reactions.
2. **Messaging never auto-enters Activity.** MessageSent bodies / Direct / Team transcripts stay in M2.4 collaboration only.
3. **Private Calendar / Message content never enters** merely because it mentions the Project.
4. **Activity is not a backdoor into Audit or Messaging.** Audit-only security events require `organization.read_audit` and stay behind Audit UX (out of scope).
5. **Requires `project.read`.** Each item independently respects source-domain AuthZ; prefer suppress/omit protected details (no leak placeholders naming hidden sources).
6. **Gate / Exception invariants preserved in examples:** READY ≠ RELEASED; Formal Exception ≠ SATISFIED; RELEASED ≠ RELEASED_WITH_EXCEPTION.
7. **Issue ≠ Task** preserved side-by-side (RESOLVED ≠ CLOSED; Task done ≠ Issue resolve ≠ Milestone ACHIEVED).
8. **Filter chips are UX facets**, not invented domain entities: Documentos/Revisões, Coordenação, Planejamento, Entregas, Governança, Equipe/Recursos (authorized only).
9. **Shell M2.1:** `Ativo=Atividade` on all M2.8 frames.
10. **Deep-links** to M2.2–M2.7 source surfaces re-authorize on open; Activity never mutates source owners.
11. **AuthZ:** UI affordances only; backend authoritative when implemented.

## Accessibility

- Focus order: shell nav → title → policy → chips → facetas → feed rows → inspector → deep-links.
- Status not color-only: Roboto Mono badges (READY / ISSUE / TASK / SUPPRESSED / EXCLUÍDO / AUDIT ONLY).
- Live region notes for loading/error; suppress does **not** announce hidden-source counts.
- Hit targets ≥34px; Escape closes inspector; **no message composer** (not a chat).
- Keyboard: ↑↓ feed; Enter opens detail; Tab to deep-link.
- No-permission / suppressed copy avoids leaking existence of inaccessible sources.
