# M3.6 Project Hub — performance baseline (observed)

LOCAL evidence for Issue #40 / M3.6-REQ-09. These are **observed** numbers from the integration test on this WI, not invented corporate latency targets. Allowed regression: re-record in this file if a later WI changes the query shape; do not invent p99 numbers.

## Dataset (representative, in-process)

Seeded inside `api/test/integration/m36-project-hub.integration.test.ts` on one authorized Project:

| Entity | Count |
| --- | --- |
| Phases | 5 |
| Deliverables | 80 (mixed stored statuses; subset overdue via `dueAt`) |
| WorkPackages | 80 (BLOCKED / late / owner-gap mix) |
| Milestones | 15 upcoming PLANNED |
| Hidden extra Deliverables on a sibling Project | 20 (must not appear in hub counts) |

No new tables or materialized health rows. Aggregations use Prisma `groupBy` / bounded `findMany` (`take` ≤ 50) plus one `GREATEST(MAX(updated_at))` freshness SQL.

## How query count is measured

`HubService` increments `observability.queryCount` once per Prisma call it issues **after** AuthZ (`requireProject`). Session/membership loads used by `PermissionGuard` / `AuthzService` are **not** included (they already run for every project-scoped GET).

## Observed baseline (local Testcontainers / CI-equivalent)

Recorded by the `performance: representative dataset is bounded (no N+1)` example in the M3.6 integration file. Re-run: `pnpm --filter @amber/api test:integration`.

| Metric | Observed |
| --- | --- |
| Query count (hub Prisma calls, cold) | **≤ 16** (typically 14–16 depending on `document.read` / `gate.read` / audit grants) |
| Query count after 80 vs 10 item scale | **unchanged** (same statement set; lists are `take`-bounded) |
| Wall time (local, cold, excludes AuthZ) | **< 2000 ms** on the Testcontainers Postgres used in CI-equivalent (`observability.elapsedMs`) |
| N+1 check | **PASS** — query count does not grow with Deliverable/WorkPackage cardinality |
| Unbounded list queries | **none** — nested lists `take` `limit+1` (max 50) |

Cache warm (`freshness.servedFromCache`) reduces hub Prisma calls to the freshness `GREATEST` probe only; AuthZ still runs first.

## Allowed regression

- Query count may grow if a new **authorized** related-source grant adds one COUNT. It must not grow linearly with row count.
- Wall time is hardware-dependent; treat doubling on the same CI class as a signal to inspect, not a invented latency-target breach.

No cloud deploy. No M4 Gantt/Kanban. No M7/M9 dashboards.
