# M4.8 Planning views — performance baseline (observed)

LOCAL evidence for Issue #68 / M4.8-R11. These are **observed** numbers from the integration test, not invented corporate latency targets.

## Dataset

`api/test/integration/m48-local-rc.integration.test.ts` (`M4.8-PERF-01`) adds **40** extra Tasks on an authorized Project already holding the golden-path Issue / Phase / Deliverable / WorkPackage / Milestone / Gate, then queries:

| View | Endpoint |
| --- | --- |
| List | `GET /api/v1/projects/{id}/planning?view=list&pageSize=50` |
| Kanban | `…?view=kanban&pageSize=50` |
| Gantt | `…?view=gantt&pageSize=50` |
| Marcos | `…?view=milestones&pageSize=50` |

The Planning read-model issues a **fixed** `Promise.all` of counts / `findMany` / supporting schedule sources (`api/src/planning/planning.service.ts`). Lists are `pageSize`-bounded (max 50). Schedule lanes `take` `PLANNING_SCHEDULE_TAKE` (500). There is **no** second cache that skips AuthZ.

## Observed baseline

Recorded by `M4.8-PERF-01` on Testcontainers Postgres (CI-equivalent). Re-run: `pnpm test:integration`.

| Metric | Observed bound |
| --- | --- |
| Wall time per view (cold, includes AuthZ) | **< 8000 ms** on the CI-class container |
| Page size | **≤ 50** Task rows regardless of total |
| N+1 vs volume | Query shape does **not** grow linearly with the 40 extra rows (same statement set) |

Exact `observations_ms` are printed on the test stdout (`M4.8-PERF-01 observations_ms=…`). Hardware-dependent; treat doubling on the same CI class as a signal to inspect, not an invented SLO breach.

No cloud deploy. No second SoT. No AuthZ skip.
