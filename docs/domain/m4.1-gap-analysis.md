## Figma Kanban labels vs frozen Task lifecycle

Frozen machine (R05 / `packages/shared/src/planning.ts`):

```
TODO → IN_PROGRESS → BLOCKED | DONE
         CANCELLED (side from TODO | IN_PROGRESS | BLOCKED)
```

Figma Kanban `242:6635` columns: **PLANEJADAS**, **EM ANDAMENTO**, **EM RISCO**, **BLOQUEADAS**.

| Figma column | Mapping | Class |
| --- | --- | --- |
| PLANEJADAS | stored `TODO` **and** `late === false` | derived projection |
| EM ANDAMENTO | stored `IN_PROGRESS` **and** `late === false` | derived projection |
| EM RISCO | stored `TODO` or `IN_PROGRESS` **and** `late === true` | derived projection — **not** a Task status |
| BLOQUEADAS | stored `BLOCKED` (late or not) | stored status. Late+BLOCKED stays here, not EM RISCO |
| (no column) DONE | stored `DONE` | List / inspector / Gantt bar. Not a Kanban column in this frame |
| (no column) CANCELLED | stored `CANCELLED` | List filter / inspector. Not a Kanban column |

Rules:

1. Dragging a card between Kanban columns is a **status command** on the Task aggregate (or a no-op if only `late` changed). It must not write a Portuguese label.
2. A card cannot appear in two columns.
3. `EM RISCO` is **never** written to `planning.tasks.status`.
4. Dates/progress edits must not move the card except via the derived `late` flag.

Status chips that repeat those Portuguese words on List/Gantt are the same mapping. English stored enums remain the API contract.
