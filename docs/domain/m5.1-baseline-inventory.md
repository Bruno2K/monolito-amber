## R02 — Membership, Team, source aggregates, primitives

### OrganizationMembership (`org.organization_memberships`)

| Field | Stored | Notes |
| --- | --- | --- |
| id, organizationId, userId | yes | UNIQUE `(organizationId, userId)` |
| type | yes | INTERNAL / EXTERNAL / ADMINISTRATIVE (`membership.ts`) |
| status | yes | INVITED / ACTIVE / SUSPENDED / REMOVED |
| version, deactivatedAt, timestamps | yes | SUSPENDED/REMOVED revoke immediately (`shouldRevokeOrgAccess`) |

M5.0 Direct identity uses this **immutable id**. Reactivating the same row may restore Direct access; a **new** membership id does not inherit history (`newMembershipInheritsDirectHistory`).

### ProjectMembership (`project.project_memberships`)

ACTIVE OrgMembership required to become ACTIVE. Org suspension/removal overrides Project access. **Team/Calendar/Messaging never write this table.**

### Team / TeamMembership (M3.3)

`org.teams`: name, version, `archivedAt` (null = ACTIVE).  
`org.team_memberships`: UNIQUE `(teamId, organizationMembershipId)`; status CHECK `ACTIVE \| SUSPENDED \| REMOVED`; same-tenant trigger.  
TeamMembership ≠ ProjectMembership (`teamMembershipImpliesProjectAccess` is false). Removing TeamMembership must immediately drop Team-derived Calendar grants and Team chat at evaluation time (R-1.5; encoded in `effectiveCalendarRole` / `teamConversationAccess`).

There are **no** `team.*` permission codes on this tip. Team directory for Calendar sharing is planned as ACTIVE internal discovery + external minimum-necessary (R-1.5 §5). M5.1 does **not** add `team.*` (would be org-admin catalog work, not required for grant/chat evaluation).

### Task / Milestone (Planning — M4 KEEP)

See [m4-planning-scheduling-contract.md](./m4-planning-scheduling-contract.md) and [m4.1-baseline-inventory.md](./m4.1-baseline-inventory.md). Stored Task statuses TODO/IN_PROGRESS/BLOCKED/DONE/CANCELLED. Milestone stored PLANNED/ACHIEVED/CANCELLED; AT_RISK/MISSED derived. FS dependencies only. Completing a Task does not achieve a Milestone or deliver a Deliverable.

Referenced Calendar events may point at Task/Milestone **ids** only. Projection re-reads Planning. Calendar EDITOR cannot PATCH Task status.

### Deliverable (Operations — M3 KEEP)

`operations.deliverables`. Linear lifecycle; DELIVERED explicit. Ownership XOR user|Team. Team owner ≠ Project access.

### Gate (Governance — KEEP)

`governance.gates`. READY ≠ RELEASED. Formal Exception sole bypass. No `gate.override` (`FORBIDDEN_PERMISSIONS`, `pnpm assert:no-gate-override`).

### Audit / outbox / idempotency

- `audit.audit_events` insert-only (ADR-008). App role REVOKE UPDATE/DELETE.
- `jobs.outbox_messages` transactional (ADR-010).
- `jobs.idempotency_records` UNIQUE `(organizationId, key)`.
- Optimistic `version` on contended aggregates.

M5 mutations reuse these primitives. MessageSent is **not** duplicated into Audit by default (R-1.5); MESSAGE_EDITED / MESSAGE_DELETED are.

### Authorization primitives

Closed catalog in `packages/shared/src/permissions.ts`. Role templates in `role-templates.ts`. `AuthzContext` is org- vs project-scoped (`authz.ts`). Deny-by-default. EXTERNAL isolation for org-wide directory. MFA for privileged templates.

**Gap for M5:** Calendar/Messaging access is **resource-scoped** (owner/grant/participant), not `project.read`. Activation tip has no `calendar.*` / `messaging.*` codes. M5.1 adds reserved `calendar.admin` and `message.moderate` only — fail-closed, not assigned, not org/project scoped (`RESERVED_COLLABORATION_PERMISSIONS`).

### Tests already on the tip (regression KEEP)
