## Command surface (additive)

| Command | Path | Permission | Body / headers | Effect |
| --- | --- | --- | --- | --- |
| Add predecessor | `POST …/tasks/{successorId}/dependencies` | `task.update` | `{ predecessorTaskId, type? }` + `Idempotency-Key` | Insert FS edge. Existing PF-1.5 path, transactional lock. |
| Remove edge | `DELETE …/tasks/{taskId}/dependencies/{dependencyId}` | `task.update` | `Idempotency-Key` | Delete the edge if `taskId` is either end. No date writes. |
| List neighbors | `GET …/tasks/{taskId}/dependencies` | `project.read` | — | Existing; enrich with re-authorized neighbor `{id,title,status}` when visible. |
| Candidates | `GET …/tasks/{taskId}/dependency-candidates?q=` | `project.read` | — | Same-Project Tasks excluding self and existing predecessors. Bounded. Omit foreign. |

`POST …/status` `/start` `/complete` stay the lifecycle surface. They now return explainable `blockers` when FS predecessors are incomplete.

## Stable rejection reasons (not permission codes)

| `reason` | HTTP | When |
| --- | --- | --- |
| `DEPENDENCY_KIND_UNSUPPORTED` | 409 `PLANNING_STATE` | `type` present and ≠ `FINISH_TO_START` |
| `DEPENDENCY_SELF` | 409 `PLANNING_STATE` | predecessor === successor |
| `DEPENDENCY_DUPLICATE` | 409 `PLANNING_STATE` | unique pair already exists |
| `DEPENDENCY_CYCLE` | 409 `PLANNING_STATE` | direct or transitive cycle |
| `DEPENDENCY_RETROACTIVE` | 409 `PLANNING_STATE` | unfinished pred attached to started/completed successor |
| `DEPENDENCY_PREDECESSOR_INCOMPLETE` | 409 `PLANNING_STATE` | start/complete while any pred ≠ DONE |
| `DEPENDENCY_DATE_SHIFT_REJECTED` | 409 `PLANNING_STATE` | dep command body includes date/status mutation fields |
| (none / generic) | 403 `TENANCY_DENIED` | missing, cross-Project, cross-Org, or unauthorized id — omit-not-leak |
| (none) | 400 `IDEMPOTENCY_REQUIRED` | missing key on create/remove |
| (none) | 409 `IDEMPOTENCY_CONFLICT` | key reused with different hash |
| (none) | 409 `OPTIMISTIC_LOCK` | stale `expectedVersion` on start/complete |

## Planning read-model extras (additive; same store)

Each `PlanningTaskRead` gains (computed from the already-loaded Project edge set — no per-row query):

| Field | Derivation |
| --- | --- |
| `dependencyStartBlocked` | `prerequisitesBlockStart` on authorized predecessors |
| `startBlockers` | `{ predecessorTaskId, status, title?, message }[]` for preds ≠ DONE |
| `predecessors` / `successors` | `{ dependencyId, taskId, title?, status }[]` — title omitted if not re-authorized |

These do **not** write `status` and are **not** Task `BLOCKED`.
