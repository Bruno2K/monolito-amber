## Schedule read-model extras (additive; same store)

| Field | Derivation |
| --- | --- |
| `schedule.dateRange` | `{ start, end }` from min/max of authorized lane dates; fallback window around `generatedAt` when no dates |
| `schedule.take` | `PLANNING_SCHEDULE_TAKE` (500) |
| `schedule.truncated` | true if any entity `findMany` hit the take |
| `schedule.canEditTaskDates` | session has `task.update` and project is not archived |
| `schedule.lanes[]` | Phase / Deliverable / WorkPackage / Task / Milestone rows with `kind`, `domain`, `sourceId`, parent, depth, start/end |
| `schedule.links[]` | FS edges where **both** Task ids are in the authorized schedule task set |

`tasks` / `milestones` / `dependencies` / pagination stay unchanged for List and Kanban. Schedule tasks use the **same `where`** as List but are not page-sliced (bounded by take). That is the same store, not a second schedule database.

## Date edit → command map (not a new machine)

| Intent | Command | Permission | Rejection |
| --- | --- | --- | --- |
| Change Task `plannedStartAt` / `dueDate` | `PATCH …/tasks/{id}` + `expectedVersion` + optional `Idempotency-Key` | `task.update` | CAS 409; archived; missing permission |
| Shift successors / propagate / parent-child cascade | **Reject** `DEPENDENCY_DATE_SHIFT_REJECTED` | — | Never writes other rows |
| Start successor while pred incomplete | existing `POST …/start` | `task.update` | `DEPENDENCY_PREDECESSOR_INCOMPLETE` (unchanged) |
| Phase / Deliverable / WP / Milestone date | **Not from Gantt** in this WI | owner APIs remain | Display-only lanes |

Dates still never write `status`. Lateness stays derived.
